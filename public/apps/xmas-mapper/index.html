xmas-mapper

i have a Govee H6871 tree light: 375 LEDs you can set one by one. but only via. app. The open lan api, of course, doesnt support to adress each LED, and turning the tree into a 3D point cloud.

had the idea in 2025 · working since nov. 26 · code on GitHub · jump to the demo

the plan

wrap the string around a tree however you want. then:

  1. talk to the light over Bluetooth
  2. which encodes the LED id into a blinking pattern
  3. film it, find the bright blobs and assign temporary IDs
  4. blobs should stay over frames
  5. play effects that use real positions: a sweep from bottom to top, snow falling,

step 1: cracking the bluetooth

this light only answers to encrypted packets. i logged the Govee Home app with Apple's PacketLogger and stared at bytes for way too long. i researched and found out, that govee is using a 16-byte handshake key, then AES-128-ECB for full blocks and RC4 for leftover bytes. the handshake is always the same, so i can just hardcode it 

key    = "MakingLifeSmarte"         # 16 bytes, for the handshake
cipher = AES-128-ECB(full 16-byte blocks) + RC4(leftover bytes)
TX e7 01 <random>  →  RX e7 01 <session key>

after that you can draw: a list of color groups, each with the LEDs it lights. the annoying part was splitting. the app cuts big drawings into 505-byte parts, numbers them, and the light only draws as many parts as the header announces. one wrong byte and nothing happens, no error. all the details are in H6871.md.

step 2: every LED says its own name

the camera has to tell 375 LEDs apart. blinking them one after another would take forever, so they all blink at once, each one its own color code. the ID becomes base-4 digits, and each digit is one of 4 colors (never white or black). a check digit at the end catches misreads.

each color is sent twice: first normal, then inverted (red, then cyan). the camera doesn't need to know what "red" looks like in my room. it only checks whether each channel got brighter or darker. that's basically Manchester code with colors. a white flash separates the digits.

try it: blink an LED ID

step 3: finding the dots

the first try with OpenCV is simple: grayscale, blur, threshold, erode, dilate, then keep the blobs that are big enough. on a dark photo it already finds the LEDs nicely
